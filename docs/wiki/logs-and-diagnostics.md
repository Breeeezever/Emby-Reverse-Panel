# 日志与诊断

客户端故障优先看“请求日志”，服务启动和监听故障再看系统运行日志。

![请求日志，示例数据](https://raw.githubusercontent.com/snnabb/Meridian/v1.13.0/docs/images/request-logs.webp)

## 请求日志

支持按站点、日期、状态、资源类别和关键词筛选。常用字段包括节点、状态码、客户端 IP、客户端 / 上游 UA、后端地址和时间。

在“全局设置 → 日志设置”可以：

- 开关日志记录与查询。
- 选择 INFO 常规记录或 ERROR 仅异常记录。
- 设置保留周期，范围为 `1–365` 天，默认 30 天。
- 选择要记录的请求类别。
- 在高级设置中分别控制写入字段与展示列。

**隐藏一列只影响界面显示，不等于停止保存该字段。** 要减少保存内容，应调整写入字段。默认可能不记录图片和元数据，查找此类请求时先检查类别开关。

日志不保存请求查询参数、令牌、Cookie 或正文。客户端 IP、UA 和后端 authority 仍可能包含个人或部署信息，公开排查前需要脱敏。

## 常见状态

| 状态 | 排查方向 |
| --- | --- |
| `200` / `206` | 正常响应或分段媒体响应；仍需确认客户端可解析内容。 |
| `301` / `302` / `307` / `308` | 检查实际跳转是否符合播放策略，是否存在循环。 |
| `401` | 上游认证、用户状态或客户端令牌。 |
| `403` | 上游权限、客户端限制或 Meridian 配额；结合错误信息判断。 |
| `404` | 入口路径、上游资源或动态播放 capability 是否失效。 |
| `421` | Host 未匹配已配置的面板或站点域名。 |
| `502` / `504` | 回源连接、TLS、DNS、超时或受限动态目标。 |
| `503` | 上游服务状态，或动态运行容量 / 速率预算。 |

## 没有看到日志

先排除：

1. 日志已关闭或处于 ERROR 模式。
2. 请求类别或写入字段被关闭。
3. 当前站点、时间、状态筛选隐藏了结果。
4. 配置了写入延迟，或异步记录仍未刷新。
5. 媒体使用直连，根本没有经过 Meridian。

这些都排除后，才检查请求是否到达入口服务器：DNS、客户端地址、防火墙、CDN、代理路径与监听状态。

## 客户端 IP 归属地

开启相关字段时，归属地可通过外部查询服务取得。默认端点为 `https://api.ip.sb/geoip/{ip}`，会向该服务发送被查询的公网客户端 IP，并缓存查询结果。

不需要外部归属地查询时设置：

```dotenv
CLIENT_IP_REGION_ENDPOINT=off
```

也可配置带 `{ip}` 占位符的 HTTPS 服务。没有归属地结果不代表请求失败，日志中的 IP 与请求状态仍可用于排查。

## 故障诊断

侧边栏“故障诊断”可检查主回源、播放回源、备用线路、TLS 和客户端标识。

将检测结果与实际客户端请求对照：

- 主地址正常，媒体节点失败：重点检查播放回源或自动发现。
- 服务器检测正常，客户端直连失败：重点检查客户端的网络与媒体源证书。
- 登录成功，播放时出错：筛选播放、视频或分片请求。

检测请求不会替你完成真实用户登录或完整播放。

## 系统运行日志

标准 Linux 安装：

```bash
sudo journalctl -u meridian -n 100 --no-pager
```

Docker：

```bash
docker compose logs --tail 100 meridian
```

容器首次日志可能含初始化令牌。分享前删除令牌、密钥、真实域名、IP 和媒体链接。完整排查流程见 [故障排查](troubleshooting.md)。
