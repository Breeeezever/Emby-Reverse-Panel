# 高级策略

高级策略按站点配置。普通接入可先使用默认 UA 透传、不限流、关闭缓存，再根据实际需求调整。

## 主备线路

在“基本配置 → 备用地址”增加线路，最多 **1 条主线路 + 7 条备用线路**。每条可设置名称、地址和启用状态。

- 备用地址不能重复主地址或其他已启用地址。
- 正常请求优先使用主线路，失败后尝试符合条件的备用线路。
- 网络错误以及 `500`、`502`、`503`、`504` 可触发重试；正常认证失败或资源不存在不会被当作可任意重试的故障。
- GET / HEAD 支持线路重试；PlaybackInfo POST 仅在正文可安全、有界重放时重试，普通写操作和 WebSocket 不随意重放。
- 失败线路会短暂冷却。后续请求尝试主线路恢复，成功后回切；这是请求驱动的行为，不是承诺现有播放无缝迁移。

运行“测试连接”检查全部地址。备用线路应提供同一套可兼容的 Emby 内容和认证，否则网络切换成功后仍可能无法播放。

## UA 与客户端身份

| 模式 | 行为 |
| --- | --- |
| 透传 | 保留客户端的原身份，默认。 |
| Infuse / Web / 客户端 | 使用对应预设。 |
| 自定义客户端 | 填写 User-Agent、Emby Client 与 Emby Version。 |

自定义身份只改写对应 UA、Client、Version，不改变 Device 与 DeviceId。上游有客户端策略时，先确认所需身份，不要同时改变多个参数再排查。

## 真实客户端 IP

可选择同时发送 `X-Real-IP` 与 `X-Forwarded-For`、只发送 `X-Real-IP`，或不透传。

Meridian 不直接采信任意客户端提供的转发头；只有来源命中 `TRUSTED_PROXY_CIDRS` 时才采用经过校验的代理信息。经 CDN / Docker / 网关访问时，先正确配置 [反向代理](reverse-proxy.md)，再启用相应模式。

## 固定上游 Header

适合上游明确要求的自定义头。值通过独立的 `UPSTREAM_HEADER_KEY` 加密保存，管理 API 不回显已保存的明文或密文。

发送范围是主回源的**精确协议、主机与有效端口**。它不会随跨域跳转传播，也不会自动交给独立播放回源。

例如配置到 `https://emby.example.com:443` 的 Header，不自动匹配 `http://emby.example.com:8096`。

不能覆盖 Authorization、Cookie、Host、转发头或 hop-by-hop 等保留 Header。修改主回源的 authority 时，未重新填写的旧固定 Header 会被清除，避免将凭据发送到新的目标。

缺少 `UPSTREAM_HEADER_KEY` 时，不能新增、重命名或修改 Header 值；可删除旧配置，补齐原密钥并重启后恢复编辑。

## 图片与静态资源缓存

在“高级策略”启用缓存，可以设置：

| 项目 | 范围 | 默认值 |
| --- | --- | --- |
| 缓存时间 | 1–720 小时 | 24 小时 |
| 容量上限 | 1–20480 MB | 512 MB |
| 自定义规则 | 每行一条，支持 `*` | 界面预设的图片与静态路径 |

缓存默认关闭。媒体流、认证和私有响应不缓存，规则也不能把不符合安全条件的响应强制变成可缓存内容。

通常保留默认规则即可。确需匹配特定静态路径时，再展开自定义规则；不要把所有请求都设为缓存对象。

缓存目录默认在数据库旁的 `asset-cache` 中，可用 `ASSET_CACHE_DIR` 指定。缓存不是备份的一部分，恢复后按实际请求重建。

## 配额与限速

流量额度使用 GB，`0` 表示不限；单连接限速使用 Mbps，`0` 表示不限。计费方向、周期和直连的区别见 [流量与配额](traffic-and-quota.md)。
