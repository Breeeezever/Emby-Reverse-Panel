# 播放模式

在“站点编辑 → 播放设置”中选择回源模式。先确保主地址、入口与 Emby 登录正常，再调整播放策略。

![播放设置](https://raw.githubusercontent.com/snnabb/Meridian/v1.13.0/docs/images/playback.webp)

## 三种模式对比

| 模式 | 视频由谁访问 | 配置方式 | 适合 |
| --- | --- | --- | --- |
| 自动发现 | Meridian 代理媒体后端 | 自动识别重定向、PlaybackInfo 和支持的清单 | 上游媒体地址经常变化或存在重定向。 |
| 手动填写 | Meridian 代理配置的回源 | 指定播放地址与额外播放节点 | 已知播放后端，需要明确配置。 |
| 直连播放 | 客户端直接访问媒体源 | 选择直连，主地址继续用于普通请求 | 客户端可访问媒体源，希望减少服务器媒体带宽。 |

三种模式都保留登录、普通 API 和海报等请求的代理。直连还保留字幕等非主媒体请求的代理；媒体清单、分片和主媒体请求可交给客户端直接访问。

## 自动发现

默认采用 **Compatible**，识别 HTTP 重定向、PlaybackInfo、HLS 和 DASH 中受支持的媒体地址，生成 Meridian 的受限播放路由。

部署必须有独立的 `DYNAMIC_ROUTE_KEY`。自动发现限制动态目标的协议、端口、网络地址和响应结构，不会变成允许任意目标的开放代理。

遇到复杂上游时先检查观察记录，再调整兼容级别；详细边界见 [自动发现](auto-discovery.md)。

## 手动填写

“播放回源地址”填写明确的后端，例如：

```text
https://playback.example.com:443
```

留空时沿用主地址。可补充额外播放节点，以允许上游跳转到这些已配置的媒体 authority。

没有写协议时，`443` 端口识别为 HTTPS，其余为 HTTP；建议填写完整 URL，避免协议猜测。节点的协议、主机和有效端口均参与匹配，只填写相似域名并不能匹配另一个端口。

手动目标是管理员明确指定的回源，自动发现的网络限制不会自动扩展成任意私网访问权限。

## 直连播放

客户端从 Meridian 获取登录与媒体信息，再直接请求原媒体 URL。Meridian 对已识别的主媒体重定向和 PlaybackInfo 播放地址按直连方式处理。

在切换前确认：

- 客户端设备能访问媒体域名、协议和端口。
- 媒体源的证书对客户端有效。
- 客户端能满足媒体源需要的认证、请求头和清单访问要求。
- 上游返回的地址不是只能在服务器内访问的私网路径。

直连的视频流量不经过 Meridian，因此不计入 Meridian 的代理流量、配额和限速。登录、海报、字幕及普通 API 等仍经过代理的流量继续计入。

浏览器可能额外受到跨域、混合内容或媒体源 Header 策略限制；某个原生客户端能播放，不代表浏览器一定能播放。

## 如何判断选对了

| 现象 | 优先处理 |
| --- | --- |
| 自动发现正常播放 | 保留 Compatible，不必增加手工节点。 |
| 观察记录提示网络目标被拒绝 | 核对实际媒体节点与安全边界，不要仅提高等级。 |
| 媒体地址固定但自动识别不了 | 试用手动填写并检测该回源。 |
| 直连后可以登录、无法播放 | 在客户端网络中验证媒体源，必要时改回代理模式。 |
| 代理播放成功但服务器带宽有限 | 可测试直连，同时接受其流量无法由 Meridian 限制。 |

连接检测不能模拟用户认证、转码、字幕和客户端网络。最终以实际播放和拖动进度结果为准。
